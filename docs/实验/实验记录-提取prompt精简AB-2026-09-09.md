## 1. 动机

system prompt 过长（≈850 tokens/次，占每次 prompt 总量 45-60%）且"宁多勿漏"教模型超发，
是 8192 输出截断的诱因之一。验证精简 prompt 能否：压超发 → 降截断/省 token，同时**不丢精确信息**。

## 2. 方法（单臂回放 + 双臂加宽）

- **主 3 段**（layer2_10/13/20 第 3 会话，即 run_7a2a539541 重入库段）：
  候选 v1 单臂 → 基线 = 今晨旧 prompt 实测（提取账 + token 统计，已在手，无需重跑）。
- **加宽 2 段**（layer2_01 conv1、layer1_04）：**双臂**（旧 vs 新同会话真对比）。
- 量测同口径：calls / 截断空 / 切段 / repair / 降级行（FactExtractor 统计）+ in/out tokens
  （Recorder 累计 chat_outcome usage）+ facts 数 + **数字保真率**（dialog 中含精确 token 的句子
  被产出事实 token 覆盖的比例，防"瘦身丢数字"）+ 耗时。
- 对话序列化与生产一致（`json.dumps(m, ensure_ascii=False)` 逐条，'\n' 连接）。

## 3. Prompt 双方

**线上现行**（2461 字符 ≈850 tok，模板指纹 c8edb6a95351，未改动）：
长散文规则（提取标准/不要提取/提取规则三节重复表达"只提取持久信息"）+ 9 类 key 候选表
（~1630 字符）+ 5 个精确值长示例 + "宁多勿漏""尽量提取"措辞。

**候选 v1**（1291 字符 ≈430 tok，-47%）：见下全文（本次实验对象，**未上线**）：

```
你是一个信息提取助手，从对话中提取值得长期记忆的事实。
事实句语言与对话一致（英文对话一律输出英文 "User ..." 句式；中文对话才用中文）。

## 提取标准
只提取用户明确陈述、持久、对未来交互有价值的信息（身份/联系方式/财务/偏好/健康/工作/家庭/教育等）。
不要提取：客服客套、瞬时决定（如"今天天气不错"）、与用户无关的内容。
宁缺毋滥：拿不准是否长期价值的不提取；精确信息宁可多收（见规则 4），叙述性信息从简。

## 规则
1. 每条事实独立成句（英文 "User ..."，中文 "用户 ..."）。
2. category 从以下列表选择：{categories_section}
3. key 是稳定字段名：同一概念只用一个 key、全程复用，禁止为同一事实发明近义 key。
   常见 key 参考：
   personal: full_name, date_of_birth, ssn
   contact: email, phone_number, address, emergency_contact
   finance: account_number, card_number, balance, claim_number, monthly_fee, amount
   preference: seat_preference, meal_preference, communication_preference
   health: allergy, medication, doctor_name, medical_history
   travel: confirmation_number, flight_number, departure_time, rental_confirmation
   education: course_name, professor, schedule
   family: spouse_name, child_name, relationship
   work: employer, occupation, income
   其他场景可自拟 key，但语义精确、同类复用。
4. 金额/编号/日期/时间/百分比/账号等精确值原样保留（含 $、千分位逗号、连字符），
   对话中新产生或变更的精确信息同样逐条提取（如 "User's claim number is CLM-2024-894327"）。
5. 单次最多输出 {max_facts} 条——优先保留最有长期价值与最精确的条目。

## 输出格式（JSON 对象，facts 为数组）
{"facts": [{"fact": "User's checking account number is 4429853327", "category": "finance", "key": "checking_account_number", "value": "4429853327", "confidence": 0.9}]}
```

## 5. 判读

- ✅ 精简 + "宁缺毋滥"确实治超发：**截断全清零**、calls 3-4、耗时 48-62s（旧 135-146s）、
  out tokens 降 30-50%。
- ❌ **但精确信息被误伤殆尽**：facts 掉到旧臂 1/3~1/2；数字保真 0%-25%（13-c3 为 0%——
  一个数字句都没保住）。layer2 用例核心就是金额/日期/编号 → **候选 v1 不可上线**。
- 根因：把全局「宁多勿漏」翻成「宁缺毋滥」——压住了叙述性超发，但**精确值也一并被砍**。
  旧 prompt 的真问题不是"提太多"而是"不分轻重地提太多"。

## 6. 结论与下一步（v1.5）

正确平衡 = **精确值宁多勿漏，叙述宁缺毋滥**（把"宁可多收"限定在含金额/编号/日期/时间的
句子）；恢复 2~3 个精确值场景示例（claim 编号 / 金额变更 / 时间线），v1 全删过头；
保留精简结构与输出预算约束。v1.5 待用户确认后迭代（同 5 段复测，仍零落库）。

关联架构议题（待方案）：prompt 文本与 LLM 模型强耦合，应引入"任务契约 vs 模型画像
（provider+model → prompt/response_format/max_tokens/分段 knobs）"分层，见会话记录。

## 7. v1.5 迭代结果（2026-09-09 追加）

v1.5 prompt（1512 字符 ≈504 tok）：规则 4 精确值宁多勿漏（最高优先级）+ 恢复 3 个
精确值示例（claim/退款链/学费多值句）；规则 5 叙述宁缺毋滥（约束明确限定非精确叙述）。
全 5 段单臂跑（机读 scripts/ab_extract_results_v15_2026-09-09.json）。

| 会话 | 旧(calls/截断/facts) | v1(facts/保真) | v1.5(calls/截断/facts/保真) |
|---|---|---|---|
| 10-c3 | 5/2/40 | 16/7% | 5/1/18/13% |
| 13-c3 | 5/1/47 | 14/0% | 3/0/8/0% |
| 20-c3 | 6/2/12 | 5/25% | 4/0/9/0% |

判读：
- ✅ 相对 v1 修复一半：L2-01-c1 保真 43→62%（=旧水平）、facts 密度回升；截断仍 0-1。
- ❌ 仍不达标：主 3 段 facts 18/8/9（旧 40/47/12，仍少一半以上）；13/20 数字保真仍 0%；
  L1-04 保真 31% vs 旧 53%。
- 两版语气实验（v1 全局宁缺毋滥 / v1.5 精确宁多勿漏）在「压制超发 ↔ 保住数字」间震荡，
  **提示词文本不是主杠杆**；怀疑杠杆在分段/每段 max_facts（35 条/60 上限的高密度会话
  模型被迫选择性输出→丢数字）。
- **度量盲区（重要）**：本实验 cov 只统计 LLM 结构化 facts；生产链路在结构化之后还有
  fallback_numeric_facts + prune_redundant_verbatim 把含数字的原句补入库（extractor 外）。
  端到端数字回忆未必如 cov 所示崩塌——需把 verbatim 兜底计入再判真实差距。
- 下一步候选：A) 度量改为「结构化+verbatim 保留后」总覆盖再对比；B) 转向分段/预算
  杠杆（如 MAX_MSGS 25 + max_facts 对精确值放行），不再磨 prompt 文本。

## 8. 关思考模式重测 v1.5（2026-09-09 追加，重大发现）

探测实证：deepseek-v4-flash **默认开启 thinking**，reasoning_content 计入
completion budget——提取这类简单结构化任务被思考吃光 8192 预算导致 content 空
截断、延迟 30-68s/次、completion tokens 虚高（成功调用 5-7.7k 大部分是思考）。
落地：memory_settings.DEEPSEEK_THINKING=False（默认关，调用带 extra_body
thinking disabled，可配回 True）。

|---|---|---|
| 10-c3 | 30.7k/18/13%/147s | **2.9k/51/73%/9s** |
| 13-c3 | 6.8k/8/0%/22s | **1.4k/21/100%/3s** |

结论：facts 全面回升（8→21、18→51）、数字保真 0-13% → 71-100%（L1-04 例外

## 1. 实验设计

- **用例集** = 上一轮 layer2 实测 `run_2bf4dafd1b`（5/20）的**全部 15 个失败用例**。
- **形态** = layer2 天然多会话：
  - 历史 = `conversations[0..n-2]`（旧 prompt 提取，模拟真实落库历史）；
  - 词表 = 历史 facts 归一后的 `(category, attribute)` 集合（**两臂共用同一份**，公平）；
  - 目标 = `conversations[n-1]`，两臂各跑一次。
- 每例词表规模 25–111 条（超过 `EXTRACT_ATTRIBUTE_HINTS_MAX=60` 的历史例按线上规则截断后注入）。

### 2.3 目标用例（§8.2 病灶）确实被治住

L2-12 矛盾财务指令 = 主方案 §8.2 的漂移病灶（`wire_amount` vs 泛词 `amount`）：

```
old：复用率 46%，12 个清单外新属性（含 finance/final_wire_amount、finance/account_type、
     finance/deposit_date、finance/cutoff_time…），facts 26
new：复用率 94%，仅 1 个新属性（finance/deposit_date），facts 18 → 18→11 属性
```

即：**模型不再给同一桩电汇另起命名空间**，属性收敛到清单内——这正是 D4-1.5 的设计目标。

## 3. 代价与反例（不装门面）

1. **prompt tokens +23.9%**：词表直接进 system prompt 的必然成本（≤60 条/次）。
2. **平均数字保真 −2.9pp**：5 例下降明显（L2-20 100%→75%、L2-16 100%→83%、
   L2-19 100%→92%、L2-08 89%→81%、L2-05 83%→78%），其余持平或上升（L2-15 82%→100%）。
   单轮证据，**不能排除采样噪声**，但方向上是「更长的 system prompt 稀释精确值注意力」
   这一已知风险，需多轮复核。
3. **L2-10 反例（唯一全面变差）**：复用率 42%→33%、新属性面 19→31、facts 38→51。
   新键集中在 `companion_*`（同行人维度）与 `current_*`——
   更像是「模型把同行人与本人拆成了两组属性」，**结构上未必更差，但与本方案的收敛目标相反**，
   且该例 old 的 cov 已是 100%，无保真代价。
4. **回放只测提取侧**：不含检索注入与 answer 判分，端到端收益仍未验证。

## 4. 结论与下一步

- **机制成立**：属性复用率翻倍、新属性面 −24%、病灶用例 L2-12 收敛到 94%/1 个新属性，
  且 facts/属性数不塌、零截断零降级 —— 说明「给词表」确实把跨会话漂移压住了。
- **不宣布收益**：单轮 A/B + cov −2.9pp + 一个明确反例（L2-10），
  不足以支撑「默认开启」。**代码默认 `EXTRACT_ATTRIBUTE_HINTS=False`（保守）**，
  开关与状态已进 `config_snapshot`，可单变量对照。
- **下一步（需用户明确指示）**：
  1. **D4-5 端到端 layer2 复测**（重置该层记忆 → 全量重提取 → 跑分），
     建议做**单变量两轮**：`EXTRACT_ATTRIBUTE_HINTS=false/true` 同库同参数对照；
  2. 若 cov 下滑在多轮里复现，先做「词表瘦身」变体（只给同 category 的子集 / 收紧上限），
     再谈默认；
  3. L2-10 单独查明：`companion_*` 拆分是锚定引入还是既有倾向（可用无锚定臂多轮复现）。

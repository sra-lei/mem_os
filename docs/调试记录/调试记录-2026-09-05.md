## 二、7 条失败逐 case 归因

方法：对每条失败，先在 `struct_memories`（SQLite 权威源）查 judge 抱怨缺失的关键事实是否存在，
再比对本次注入（retrieved_memories）与答案（actual_answer），定位失败层。

### 2.1 layer1_02_insurance_claim（0.5）—— 回答层（注入含冲突旧值）
- **库里**：✅ CLM-2024-894327 / 新电话 916-555-8899 / "24-48 小时内" 均有。
- **注入**：同时出现两条矛盾的 Patricia 时间版本 —— `"理赔专员 Patricia Wong 将在 24-48 小时内联系用户"`
  与 `"理赔专员Patricia Wong将在48小时内联系用户"`（截断/旧版并存）。
- **答案**：只给出"48 小时内"，且未提"拨打更新后电话"。
- **根因**：① 同义事实多版本未收敛（24-48h 与 48h 并存），模型选中旧版；② 回答不完整。
- **判定**：回答层 + 轻微事实冲突。

### 2.2 layer1_13_tax_preparation（0.2）—— 检索未覆盖 + 少量提取缺
- **库里**：✅ MedConsult $5,000 / HealthAdvisors $3,500 / laptop $1,899 均有；⚠️ home office $1,525 无。
- **注入**：只有总额类（$8,500 / $6,724 / taxable $179,000…），收入来源明细一条未进 top-15。
- **答案**：只能给总额，并称"没有逐项费用记录"。
- **根因**：86 条 fact 只注入 15 条，MedConsult/HealthAdvisors 排序在 top-15 之外（检索覆盖）；
  home office 金额从未入库（提取漏）。
- **判定**：检索层为主 + 提取层少量。

### 2.3 layer1_14_cellphone_upgrade（0.6）—— 检索未覆盖

- **答案**：诚实说"颜色没有记录"——实际库里明明有。
- **判定**：检索层。

### 2.4 layer1_15_college_enrollment（0.35）—— 检索未覆盖（最典型）

- **答案**：财务部分正确，课程部分只能答"没有课表细节"。
- **判定**：检索层。

### 2.5 layer1_17_veterinary_care（0.35）—— 检索碎片 + 提取少量缺
- **库里**：✅ 血检 $285 / X光 $420 / 心丝虫 $47 独立成条；⚠️ DHPP 只存"已过期"未存 $42。

  （$770 与 $285 并列 → 与 $859 对不上）。
- **判定**：检索层（多版本碎片挤占）+ 提取层少量（DHPP $42 未入库）。

### 2.6 layer1_19_wedding_venue（0.3）—— 检索未覆盖

- **注入**：只覆盖每人 $125/$28/$153 → 总额 $22,950；支付计划/税/服务费全在 top-15 外。
- **答案**：诚实说"三次付款分期没有记录"——库里其实都有。

### 2.7 layer1_20_daycare_enrollment（0.5）—— 提取缺单价 + 回答被陈旧信息污染
- **库里**：✅ 周总额 $617.50 / 首期 $1,017.50 有；⚠️ Emma $325 / Olivia $292.50 / 用品费 $400 未单独成条。

- **答案**：把 $308.75 当成最终答案，算出 12/23 应付 $708.75（应 $1,017.50）。
- **根因**：① 单价/用品费未单独提取；② 检索把"当周调整"的临时值当权威信息注入，覆盖了正确总额。
- **判定**：提取层 + 回答层（陈旧信息污染）。
